# קונסול ניהול

כלי מקומי לניהול כל המוסכים בכל הסביבות. רץ רק על המחשב שלך, לא נבנה ולא נפרס.

```bash
npm run admin
```

נפתח בכתובת:

```
http://127.0.0.1:4180
```

## מה צריך כדי שיעבוד

| מה | למה |
|---|---|
| `.env.production.local` | מוסכים בייצור |
| `.env.local` | מוסכים בבדיקות |
| `npx supabase start` | הסביבה המקומית, אם רוצים לראות גם אותה |
| `npx supabase login` | מיגרציות ופונקציות בבדיקות ובייצור |
| `git fetch origin` | השוואה לענפים `staging` ו־`main` |

אין לקונסול קובץ סודות משלו. הוא קורא את אותם קבצים שהסקריפטים קוראים.

## איך זה בנוי

- `admin/src/` הוא הדף בדפדפן. אין בו אף מפתח, והוא מקבל רק תשובות מהשרת.
- `admin/server/api.mjs` הוא צד השרת שרץ בתוך שרת הפיתוח של Vite. רק הוא מחזיק את מפתחות ה־service_role.
- `packages/ops/` מחזיק את הלוגיקה עצמה, משותפת לקונסול ולסקריפטים בתיקייה `scripts/`. כששינוי במאגר משפיע על הקונסול, משנים שם, פעם אחת.

## הגנות

- השרת מאזין רק ל־`127.0.0.1`.
- בקשה שמגיעה עם שם מארח או מקור שאינם המחשב המקומי נדחית, כדי שאתר זר לא יוכל לקרוא את התשובות.
- כרגע כל הנתיבים הם קריאה בלבד.
- השרת מגיש לדף רק קבצים מהתיקייה `admin/` ומהספריות המותקנות. קבצי סביבה וקבצי לקוחות לא נגישים.
- הבנייה של האפליקציה, וכך גם Netlify, לא כוללת את התיקייה הזו.
- קריאת המיגרציות מסביבה מרוחקת רצה מתיקייה זמנית. הקישור של ה־CLI במאגר (`supabase/.temp/project-ref`) לא משתנה, ולכן ה־`db push` הבא לא יופנה בטעות לסביבה אחרת.
